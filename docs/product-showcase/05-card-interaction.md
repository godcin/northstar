# 05 · 卡片式交互

对话是入口。需要你做选择或确认的事，用卡片承载，让每一次选择都明确、可追溯，而不是靠猜测一句自由文本的意思。

## 为什么用卡片

- 固定选择的流程，必须用卡片按钮承载，不靠自由输入来回确认。
- 卡片提交的是明确的选择，系统按卡片对应的对象和动作续接，不靠解析按钮文字或卡片文案。
- 聊天记录保持干净：按钮点击不写入对话。

## 卡片的种类

| 卡片 | 什么时候出现 | 你可以做什么 |
| --- | --- | --- |
| 决策题 | 流程需要在几个方向中选一个 | 直接点选选项，也可以选择“其他”并补充说明 |
| 清单确认 | 需要逐项确认的检查清单 | 逐项确认后提交本分类 |
| 审批确认 | 文件修改或关键操作需要批准 | 批准或驳回；一次可以确认本批所有文件修改 |
| 下一步 | 完成一步之后，系统推荐接下来做什么 | 执行推荐的动作，或打开对应文档 |
| 航线 | 随时显示现在在哪、下一步能做什么 | 点击即可执行当前可用的动作 |
| 结果与状态 | 记录一次操作的结果、状态或失败原因 | 只读，供回看 |

## 怎么操作

1. 看清卡片上的问题和选项。
2. 点选或确认，然后提交。
3. 卡片变为已处理，已经提交的按钮不能重复点击。
4. 对话输入框始终可用，你可以随时补充说明或提出新的需求。

## 安全与边界

- 卡片只能提交当前待处理的那一张；过期的卡片会被拒绝。
- 同一范围内，你提出新的明确意图时，尚未提交的旧卡片会失效，不会被误提交。
- 审批和风险确认只有在你明确点击后才生效，系统不替你做决定。
- 结果与失败卡片只读，不能再次执行。

## 设计原则

- 桌面端不做卡片墙：侧边栏和输入区保持扁平，卡片只用于需要选择或确认的结构化交互。
- 卡片样式安静，不抢对话本身的注意力。

## Viewer 里的待确认卡片

Viewer 是只读工作台，待确认事项以卡片汇总，可以进入详情查看，但不在这里提交确认。
