04 · 三方 Agent 能力

编码、修复、运行验收命令这类重活，可以交给成熟的编码 Agent 执行。Northstar 负责授权、边界和验收，执行者只负责施工。

为什么要委派

  • 可以程序验收的重活，交给外部编码 Agent 完成。
  • 讨论、判断和领域操作仍由 Northstar 自己的模型流程处理。
  • 执行者自己报告“已完成”不算数，完成与否以 Northstar 的独立验收为准。

当前执行者

当前交付的第三方执行者是 Codex App Server。执行者通过适配层接入，产品流程与具体执行者分开。

委派的流程

  1. 生成委派内容：目标、验收标准、验收命令和允许改动的范围，由系统整理。
  2. 确认后才开始：确认之前不创建工作区，也不启动执行者。
  3. 在独立工作区施工：执行者只能修改确认过的范围，系统核对实际改动。
  4. 独立验收：Northstar 重跑验收命令，执行者的自验不能替代这一步。
  5. 合入与记录：验收通过后才合入代码仓，结果以卡片回到对话，改动和验收结果保存为证据。

两种委派范围

范围 什么时候用 结果
需求内委派 有进行中的需求，由开发阶段发起 经过需求阶段的门禁，验收后可以推进需求状态
工作区委派 没有进行中的需求，且现有工具无法完成的代码或文件修改 确认后执行，结果记为证据，不推进需求状态

边界与治理

  • 范围：执行者只能改动确认过的范围，不能修改需求、变更等产品真相源。
  • 授权：每次委派都需要你确认。
  • 质量：独立验收通过才算完成。
  • 证据：改动和验收结果都保存下来，可以回看。
  • 模型：一次委派开始后，即使在设置中修改模型，本次委派也不会中途切换。

中断之后

委派中断后可以按原来的确认重试，不需要重新规划，也不需要重新确认。已经交接的结果会被恢复，而不是重复执行。

不做的事

  • 不修改项目指南、需求和变更的状态。
  • 不绕过审批。
  • 不把执行者的总结当作完成依据。
  • 不在一次委派中途切换模型。
