02 · 核心价值

Northstar 用明确的职责、流程与证据，连接模型的理解能力和工程的确定性。

1. 角色清晰，交接自然

围绕 PM、Dev、QA 的职责组织任务与产物。切换角色时，继续当前需求真正需要处理的工作。

  • PM 负责产品需求与验收方向。
  • Dev 负责技术设计与实现。
  • QA 负责测试与验收证据。

2. 关键动作，按条件推进

通过显式状态、流程检查与分级审批，让重要操作先满足权限与交付条件，再继续下一步。

  • 通过显式状态和流程检查，让关键操作有据可循。
  • 分级审批，让重要操作满足权限要求后再继续。

3. 结果有依据，过程可追溯

将工具执行、文件变更与质量证据关联起来。保留记录，核实产物，而不只依赖一句“已完成”。

  • 工具执行、文件变更与质量证据关联在一起。

4. 能力扩展，边界明确

通过模块化 Skill、MCP 工具接入与模型适配扩展能力，同时沿用统一的执行与权限边界。

  • 通过模块化 Skill 与 MCP 工具接入扩展能力。
  • 可用的模型和工具取决于实际配置，相关工具调用仍经过统一的权限、执行与记录流程。

5. 卡片式交互，结构化承载选择与确认

固定选择、摘要确认与风险确认以卡片呈现，而不是靠自由文本来回。

  • 卡片提交的是结构化内容，按动作与对象标识续接，不靠按钮文字猜测用户意图。
  • 设计上要求按钮点击不写入聊天记录，卡片出现时输入框仍然可用。
