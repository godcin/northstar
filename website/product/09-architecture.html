09 · 架构与扩展

Northstar 将交互入口、研发流程、模型能力和工具执行分层组织，让 AI 在真实项目规则内工作，也为模型与能力扩展留下清晰边界。

客户端共享服务端流程

Desktop 与 CLI 通过统一 HTTP 入口提交对话、卡片和操作。服务端编排每轮请求，客户端负责输入、呈现和读取结果，研发规则由服务端集中处理。

层次职责
Desktop / CLI采集用户输入，展示交互、运行进展与正式结果。
Agent Service统一编排对话、结构化交互、模型调用和工具执行。
流程与领域规则校验需求状态、角色、版本、门禁与真实写回。
模型 / Skill / 工具提供理解、工作方法和受控执行能力。

同一产品从不同入口继续工作时，可以沿用同一套状态与规则。客户端扩展因此有明确接入点，当前产品形态以 Desktop、CLI 与 Viewer 为主。

产品管理、执行与查看分别负责

Product Service 负责产品初始化、仓库绑定和生命周期；Agent Service 负责聊天与执行；Viewer 按角色展示业务产物与协作事项。

Viewer 可以保存展示偏好，但保持业务产物只读。查看文档与推进开发分开，避免一次浏览请求附带改变产品事实。

普通推理与开发 Agent 独立配置

普通推理的 API 通道当前覆盖 OpenAI、Claude API、DeepSeek 与 GLM；开发执行的 Agent 通道目前面向 Codex App Server。实际可用模型取决于配置、账户权限和服务支持。

两个通道分别配置 provider、model 与 effort。产品分析、调研或评审可以采用合适的推理模型，编码任务保持自己的执行配置；修改普通聊天模型不会悄悄覆盖开发 Agent。

强类型契约连接模型与执行

结构化输出以 Pydantic 类型定义为依据，从同一类型生成 JSON Schema，并用同一类型校验返回内容。封闭契约使用严格约束，拒绝不属于协议的字段。

操作还绑定当次 schema、上下文指纹与约束摘要，减少模型请求和本地校验各自维护格式造成的漂移。卡片答案、计划与评审结果因而可以成为可检查、可持久化的数据。

不同模型服务对原生严格 schema 的支持不同，适配层使用相应投影方式，最终仍需本地校验。格式合法也只是执行前提，语义与权限继续由后续规则判断。

Skill 组织可组合的工作方法

Skill 索引按角色、可用工具和策略过滤；模型可以按需读取完整工作法及辅助材料。高频角色或阶段的方法还可以有限预加载，平衡上下文成本与可用性。

需求澄清、PRD、TD 与测试方法可以分别演进。Skill Loader 读取工作法与辅助材料；实际读写和状态操作通过注册工具或领域操作执行，权限和流程门禁继续由系统负责。

MCP 工具进入统一执行目录

Northstar 通过 stdio 客户端发现外部 MCP server 的工具，保留命名空间、schema 与工具集信息，再按允许范围注册到统一目录。

工具调用继续经过现有执行器、授权和 Guardrail。单个 server 接入失败会记录对应阻塞，其他已可用 server 可以继续处理。

这里提供的是外部 MCP 工具消费能力。接入范围和执行权限受配置约束，不会因为注册一个工具就获得任意文件或系统权限。

长对话有统一上下文预算

每轮使用不可变上下文快照，根据模型窗口分配历史、记忆、导航引用和工具结果预算。较早讨论可以压缩为摘要与身份引用，原始对话继续保留用于回查。

周期性从原文重新整理摘要，减少长期滚动压缩的累计偏差。窗口不明确或摘要滞后时采用保守范围，避免不同层各自截断导致上下文失联。

摘要与记忆帮助理解，仍可能有损。正式权限、需求状态、签核与完成结论，以各自负责模块的事实和证据为准。

扩展的技术原则

新能力通过模型适配、Skill、工具和结构化契约接入已有流程；输入、权限、结果与失败方式都有对应位置。架构持续演进，扩展的目标是让能力增长与工程约束一起维护。
