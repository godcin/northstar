NORTHSTAR DESKTOP / PM WORKFLOW

PM 产品交互流程演示视频

以家庭图片视频网站 media-harbor 为例，
从需求调研、逐项确认、PRD 生成与评审到 PM 签核。

  1. 02:00

    提出想法与创建需求

    描述家庭图片视频的本地浏览与打印筛选需求，建立产品上下文。

  2. 06:00

    需求调研与逐项确认

    围绕目标用户、素材来源和使用场景展开调研，逐项确认需求发现。

  3. 12:00

    补充约束与确认发现

    补充日期筛选、素材管理和打印交付规则，将实际约束纳入需求。

  4. 19:00

    生成与查看 PRD

    将确认的调研结果整理为 PRD，查看产品范围、功能需求与验收标准。

  5. 26:00

    处理评审问题

    批量修订评审发现的两项问题，回到 PRD 核对更新后的需求。

  6. 28:40

    PRD 签核

    确认 PRD 与验收范围，形成经 PM 签核的需求基线。

NORTHSTAR DESKTOP / DEV WORKFLOW

Dev 技术交互流程演示视频

承接 media-harbor 的产品需求，
从技术调研、TD 编写与评审，到需求异议收口、同步 TD 和确认实现步骤。

  1. 00:00

    技术调研

    承接已签核的产品需求，调研素材读取、格式兼容和性能容量，逐项确认技术发现。

  2. 14:00

    TD 编写

    根据确认的调研结果分批生成 TD，明确架构、关键流程、存储与验证方案。

  3. 20:00

    TD 评审

    评审技术设计，查看八项问题与依据，识别需要产品进一步裁定的业务规则。

  4. 22:00

    需求异议收口

    切回 PM 确认重复收集、日期与时区等产品决策，修订 PRD 并保留变更依据。

  5. 40:00

    同步 TD

    带着确认的产品变更切回 Dev，更新技术设计，使 TD 与新的需求基线保持一致。

  6. 48:00

    再评审与技术收敛

    再次评审同步后的 TD，逐项确认并修订七项技术问题，完成问题闭环。

  7. 1:04:00

    确认实现步骤

    在 TD 技术问题收敛后，确认实现顺序与验证方式，提交进入后续开发的依据。

NORTHSTAR DESKTOP / AI CODING WORKFLOW

Dev AI 编码交互演示视频

接续 media-harbor 的技术设计，
从确认生成代码、运行本地页面，到截图反馈、问题修复与交互优化。

  1. 00:00

    确认生成代码

    承接已确认的技术设计、实现顺序与验证方式，确认后进入 Agent 编码工作台。

  2. 02:45

    查看编码与验证进度

    Agent 拆分媒体索引、前端与运行流程，推进实现与联调，持续展示执行进展。

  3. 10:40

    运行与体验本地页面

    打开生成的网站，选择本地媒体文件夹，查看日期时间线、照片与待打印收集操作。

  4. 12:10

    截图反馈与 HEIC 修复

    把无法预览的 HEIC 照片截图带回对话，Agent 排查解码与索引问题，修复后回到页面核对。

  5. 17:10

    继续优化浏览与打印体验

    结合实际页面提出左右浏览、加入待打印和查看收集结果等改进，继续通过对话调整代码。

  6. 20:00

    回到页面查看优化结果

    查看更新后的媒体库与照片预览，体验翻页和加入待打印操作，将实际使用反馈继续带回开发。

ONE CONNECTED WORKFLOW

从想法到交付，
每一步都接得上。

围绕一条需求组织研发全过程，
让当前范围、交接条件和下一步工作清晰可见。

  1. 01

    需求分析

    澄清目标与范围，
    形成清晰的产品需求。

    PM / 产品
  2. 02

    技术设计

    连接需求与实现，
    明确方案和影响范围。

    Dev / 技术
  3. 03

    代码实现

    围绕确认的方案开发，
    保留执行与变更记录。

    Dev / 技术
  4. 04

    测试验收

    关联测试与验收目标，
    记录缺陷和质量证据。

    QA / 质量实验性
  5. 05

    发布与复盘

    核对发布与恢复准备，
    记录结果和后续改进。

    PM · Dev · QA实验性

需求有异议，回到产品确认；测试发现缺陷，交回开发修复。协作不止向前，也能有依据地返回。

公开视频展示 PM 从需求调研到 PRD 签核、Dev 从技术调研到实现步骤确认，以及 AI 编码、本地运行、截图反馈与修复迭代。Dev 签核、QA、缺陷修复、发布与复盘流程仍为实验性能力，正在持续验证与完善。

BUILT FOR ENGINEERING

让 AI 的工作，
成为可验证的工程。

把角色、版本和执行结果纳入同一条链路，
让每次推进都有可以检查的工程依据。

角色交接，带着成果继续

PM、Dev、QA 各有职责与待办。切换角色时承接当前需求的产物与阻塞，业务异议交回 PM，开发继续使用确认过的需求。

了解流程治理

结构化关联，让知识接得上

需求、技术设计、代码与验证资料保留标识、版本和关联。通过 Alignment 检查上下游覆盖与一致性，让修改影响有迹可循。

了解知识与版本

评审结论，对应具体版本

评审记录绑定送审材料与规则版本。产物变化后重新核验结论有效性，签核前检查当前范围、未解决问题与交付条件。

了解版本一致性

受管委派，明确交付范围

将目标、范围与验收要求交给外部 Agent，在受管工作区执行代码任务。Northstar 核对改动与验收结果，再按流程承接交付。

了解 Agent 委派

核对实际结果，保留执行依据

结合工具回执、文件变化与验证输出判断结果，明确完成、部分完成和待核对事项。重要操作经过权限与确认检查，过程留下记录。

了解结果核验与诊断

中断有记录，恢复有范围

用执行记录接续未完成工作，用恢复点回到选定的产品现场。分别核对代码仓、知识库仓与运行状态，让恢复结果可以逐项检查。

A LITTLE MORE CONTEXT

关于 Northstar

Northstar 主要解决什么问题？

把分散在讨论、文档和执行中的研发依据连接起来。围绕同一需求，逐步明确目标、范围、方案和验收方式；用状态、版本与执行记录说明工作进行到哪里，下一步由哪个角色承接。

需要多人才能使用 PM、Dev、QA 吗？

一个人也可以切换这三个责任角色推进自己的产品。PM 负责产品需求与业务取舍，Dev 负责技术设计与实现，QA 负责验证与质量依据。多人同时协作、人员权限和更细的职责划分属于后续规划。

产品界面在哪里运行？

Northstar 以桌面客户端作为主要交互入口。Viewer 是查看项目、需求文档与协作事项的只读工作台；CLI 可用于调试与自动化。本页包含真实 Desktop 会话录像，以及使用示例数据的 Viewer 界面。

可以接入已有的模型和工具吗？

Northstar 通过模型适配层、Skill 和 MCP 客户端接入扩展能力。可用模型和工具取决于实际配置；相关工具调用仍经过统一的权限、执行与记录流程。
