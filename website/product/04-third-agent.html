04 · 三方 Agent 能力

Northstar 可以把编码与修复交给专业编码 Agent，同时保留需求理解、授权、范围控制、独立验收和正式交付。用户能核对实际改动与交付依据。

各自负责什么

Northstar 负责整理目标、参考材料、允许范围与验收方式；编码 Agent 在受管工作区完成实现和自检；Northstar 再检查候选结果、执行验收，并记录后续交付状态。

当前用户可选的外部 Agent 通道是 Codex App Server。普通对话模型与开发 Agent 可以分别配置；具体能力取决于实际配置与授权。

从委派到交付

  1. 建立任务依据：读取当前需求和确认过的 PRD、技术调研与 TD，整理目标与参考材料。
  2. 确认任务边界：明确允许修改的范围、禁止范围和验收命令；确认后才创建受管工作区并启动执行。
  3. 在隔离环境实现：Agent 修改候选代码并自检，系统核对实际变化是否符合授权范围。
  4. 独立执行验收：Northstar 对候选结果重新运行验收命令，保存每条命令的结果与失败信息。
  5. 整合最新版本：需求交付在隔离环境核对最新 main 与需求分支，整合后再次验收。
  6. 交付到需求分支：通过后进入配对的代码与知识库需求分支；正式发布另由发布流程推进 main。

独立验收解决什么问题

Agent 的自检和完成总结有助于理解工作，但交付还需要独立核对。验收命令绑定这次任务，在实际候选工作区执行，并保留退出结果、输出与超时信息。

验收失败时，候选与失败依据保留下来，可用于修复或续接。通过这些命令证明的是对应检查满足条件，业务覆盖与 QA 质量结论仍有各自的要求。

需求任务与普通工作区任务

场景执行与结果
需求内委派与当前需求阶段、文档版本和验收依据绑定。结果进入需求分支，由对应流程检查后续推进条件。
普通工作区委派在无进行中需求时，处理已明确授权、现有注册工具无法完成的代码或文件工作。保存证据，不自动创建或推进需求。

中断、修改设置与继续执行

一次委派开始后，会固定本次执行模型。修改设置影响后续新委派，本次任务继续使用已经确认的配置。

中断后先核对原任务记录。若候选已验收、交付尚未完成，可以继续原交付，减少重复调用编码模型。目标、范围或验收标准改变时，需要重新核对授权与任务依据。

技术亮点：把实现与发布分开

受管候选工作区、独立验收、配对需求分支与正式发布分别承担不同职责。代码写完、验收通过、进入需求分支、发布到 main 是不同结果，可以逐步检查和恢复。

正式需求状态、签核和发布由 Northstar 的领域规则校验。外部 Agent 即使获得候选文档目录的写权限，也需要通过后续验收与交付流程才能成为正式产物。
