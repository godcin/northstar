06 · 外部 Agent 委派与交付

Northstar 可以把编码工作交给专业编码 Agent，在明确任务范围的受管工作区中实现，再用独立验收和交付记录核对成果。需求、授权与验收依据随任务一起传递。

分析与编码可以使用不同能力

Northstar 组织目标、参考材料、允许修改的范围和验收方式；编码 Agent 完成实现与自检；系统再核对候选变化，执行验收并记录交付状态。

当前用户可配置的外部 Agent 通道为 Codex App Server，普通推理模型与开发 Agent 可以分别选择配置。实际执行还需要对应账户、权限和工作区条件。

从确认任务到需求分支交付

  1. 建立任务依据：读取当前需求、产品需求文档、技术调研与设计，整理这次实现的目标。
  2. 确认范围与验收：明确可修改的路径、禁止范围和验收命令，再建立受管工作区。
  3. 生成实现候选：Agent 修改代码并自检，系统核对实际变化与授权范围。
  4. 独立验收：在候选工作区重新执行约定命令，保留输出、退出结果与失败信息。
  5. 整合后再次检查：在隔离环境结合观察到的最新 main 与需求分支，对确定的整合候选重新验收。
  6. 交付并读回：通过后交付到配对的代码与知识库需求分支，记录两侧版本与回执。

验收通过具体意味着什么

验收命令与本次任务绑定，检查的是候选代码在这些命令下的实际表现。失败时保留候选和失败依据，便于继续修复；通过后留下后续评审可以使用的结果。

自动化验收覆盖约定检查。QA 的测试覆盖和质量签核仍有各自的职责，发布检查也需要核对环境、步骤和回滚准备。

工作区任务与需求任务

场景组织方式
需求内编码绑定需求阶段、文档与实现步骤；验收后交付需求分支，后续推进按需求规则检查。
普通工作区任务在没有进行中需求且符合委派条件时，处理明确授权的代码或文件工作，保留执行证据。

已验收的候选可以继续交付

候选已经验收、交付尚未完成时，可以沿原任务核对并继续交付，减少重复调用编码模型。每次委派固定其执行配置，设置变化在后续新委派中生效；目标或验收范围改变则重新核对任务依据。

关于断线、结果未知与重试的处理，见 执行与失败恢复。

从代码交付到正式发布

生成候选、验收通过、进入需求分支和进入 main 分别有对应结果。正式发布需要通过配置的仓库服务和发布流程完成评审、合并及结果核对；部署到线上环境还需配套的部署执行与验证。

技术设计录像展示到实现步骤确认；AI 编码录像继续展示代码生成、本地运行、截图反馈与修复迭代。实际体验与回归检查不等同于最终质量签核。Dev 签核、QA、发布检查与复盘环节仍处于实验性阶段。
