NORTHSTAR DESKTOP / PM WORKFLOW

PM 产品交互流程演示视频

以家庭图片视频网站 media-harbor 为例，
从需求调研、逐项确认、PRD 生成与评审到 PM 签核。

  1. 02:00

    提出想法与创建需求

    描述家庭图片视频的本地浏览与打印筛选需求，建立产品上下文。

  2. 06:00

    需求调研与逐项确认

    围绕目标用户、素材来源和使用场景展开调研，逐项确认需求发现。

  3. 12:00

    补充约束与确认发现

    补充日期筛选、素材管理和打印交付规则，将实际约束纳入需求。

  4. 19:00

    生成与查看 PRD

    将确认的调研结果整理为 PRD，查看产品范围、功能需求与验收标准。

  5. 26:00

    处理评审问题

    批量修订评审发现的两项问题，回到 PRD 核对更新后的需求。

  6. 28:40

    PRD 签核

    确认 PRD 与验收范围，形成经 PM 签核的需求基线。

NORTHSTAR DESKTOP / DEV WORKFLOW

Dev 技术交互流程演示视频

承接 media-harbor 的产品需求，
从技术调研、TD 编写与评审，到需求异议收口、同步 TD 和确认实现步骤。

  1. 00:00

    技术调研

    承接已签核的产品需求，调研素材读取、格式兼容和性能容量，逐项确认技术发现。

  2. 14:00

    TD 编写

    根据确认的调研结果分批生成 TD，明确架构、关键流程、存储与验证方案。

  3. 20:00

    TD 评审

    评审技术设计，查看八项问题与依据，识别需要产品进一步裁定的业务规则。

  4. 22:00

    需求异议收口

    切回 PM 确认重复收集、日期与时区等产品决策，修订 PRD 并保留变更依据。

  5. 40:00

    同步 TD

    带着确认的产品变更切回 Dev，更新技术设计，使 TD 与新的需求基线保持一致。

  6. 48:00

    再评审与技术收敛

    再次评审同步后的 TD，逐项确认并修订七项技术问题，完成问题闭环。

  7. 1:04:00

    确认实现步骤

    在 TD 技术问题收敛后，确认实现顺序与验证方式，提交进入后续开发的依据。

BUILT FOR ENGINEERING

让 AI 的工作，
成为可验证的工程。

Northstar 用明确的职责、流程与证据，
连接模型的理解能力和工程的确定性。

角色清晰，交接自然

围绕 PM、Dev、QA 的职责组织任务与产物。切换角色时，继续当前需求真正需要处理的工作。

关键动作，按条件推进

显式状态、流程检查与分级审批，让重要操作满足权限与交付条件，再继续下一步。

结果有依据，过程可追溯

将工具执行、文件变更与质量证据关联起来。保留记录，核实产物，而不只依赖一句“已完成”。

能力扩展，边界明确

通过模块化 Skill、MCP 工具接入与模型适配扩展能力，同时沿用统一的执行与权限边界。

A LITTLE MORE CONTEXT

关于 Northstar

Northstar 与普通编码助手有什么不同？

Northstar 关注完整的研发交付过程：不仅生成代码，还围绕需求分析、技术设计、测试验收与发布确认，组织角色职责、工程产物和下一步工作。

PM、Dev、QA 是怎样协作的？

它们是同一工作流中的责任角色。PM 明确产品需求与验收方向，Dev 推进技术设计与实现，QA 建立测试与验收证据。异议与缺陷会交回对应角色处理。

产品界面在哪里运行？

Northstar 以桌面客户端作为主要交互入口。Viewer 是查看项目、需求文档与协作事项的只读工作台；CLI 可用于调试与自动化。本页包含真实 Desktop 会话录像，以及使用示例数据的 Viewer 界面。

可以接入已有的模型和工具吗？

Northstar 通过模型适配层、Skill 和 MCP 客户端接入扩展能力。可用模型和工具取决于实际配置；相关工具调用仍经过统一的权限、执行与记录流程。
