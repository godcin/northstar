08 · 执行与失败恢复

长任务会遇到断线、模型故障或进程重启。Northstar 分别保存目标、授权、执行尝试与结果，先核对已经发生了什么，再决定继续、重试或等待输入。

目标与执行尝试分开保存

ActionGoal 记录目标对象、来源版本、成功条件，以及授权角色、范围和风险上限；GoalAttempt 记录这次尝试使用的能力、参数、执行状态与回执。

一次调用失败后，原目标和已有资料仍有身份可以追查。是否完成由负责原目标的模块重新验证；工具返回成功或模型总结不能单独证明目标完成，仍需核对正式回执与成功条件。

重复提交复用已绑定的执行

结构化请求根据稳定内容指纹和作用范围认领执行。相同语义、相同绑定的当前请求可以关联原 run 与回执，让连续点击、刷新或丢失响应后的再次提交找到已有任务。

目标、参数、版本或授权变化后，需要核验它属于冲突还是新动作。去重依赖精确身份和当前执行记录，不能理解为所有外部操作永远只发生一次。

多批次操作记录部分成功

多项确认和分批写入为每批保存身份、真实状态、结果回执与恢复位置。全部成功才算完成；部分已经写入、仍有未完成项时，结果明确标记为部分成功。

例如前两批 TD 问题已处理，第三批失败，系统保留前两批成果，再从真实记录判断剩余工作。特定多批次流程有恢复 cursor，通用目标恢复仍回到原负责模块的状态与回执核验。

未知结果先核对，再决定重试

文件可能已经写入，远端也可能已经接受操作，只是响应丢失。Northstar 在有副作用的操作前绑定参数、对象、基线与预期结果，恢复时查询原回执和实际状态。

核对结果后续处理
已经完成读回结果或补齐交付，保留原操作身份。
确定尚未执行满足原授权与重试条件后，继续执行。
结果未知继续查询、对账或请求人工核对，保留不确定状态。
版本或结果冲突明确阻塞并处理冲突，再核验可继续的条件。

不同错误采用不同恢复方式

临时故障可以在有界范围内自动恢复；凭据或模型配置错误需要先修正配置；需要审批或用户答案的动作保持等待。自动恢复没有进展时，会暂停重放并保留原操作的显式重试入口。

模型服务故障不会自动扩大到修改代码、环境或权限。原目标、不可变输入、范围与验收合同仍有效时，才可以沿原确认续接；改变目标与范围需要新的授权依据。

断线重连继续观察原任务

运行事件持久化后通过 SSE 推送。客户端用事件 ID 或 cursor 接回原 run，回放已有记录后继续读取实时进展。请求被接纳、收到进度和业务正式完成分别有对应状态。

短暂断线或界面重载可以继续观察服务端原任务。进程崩溃后的执行需要核对已有结果，未知副作用不会因为重新连接而自动重跑。

停止执行与恢复历史有明确边界

取消绑定具体产品、会话与 run，等待真实执行结束的回执。系统重启则先关闭新任务准入，保存运行清单并等待受管执行收口，再停止经过身份核验的进程。

产品历史恢复会退役旧执行权和线程，由负责模块重新激活可续接的交互。恢复后的执行使用新代际，保护新现场免受旧任务迟到结果影响。

停止不会自动撤销已经发生的副作用。恢复依赖受管动作、有效回执和可核验状态；无法证明结果或归属时，会保留阻塞并要求核对。
