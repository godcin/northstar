09 · 架构与扩展

Northstar 将交互、研发规则、模型推理和工具执行分层组织。模型和工具可以扩展，产品状态、授权和执行结果仍沿同一套规则管理。

统一服务连接多个入口

Desktop 与 CLI 通过 HTTP 服务提交对话、卡片和动作，读取进度与结果。服务端集中处理流程规则，为其他客户端或脚本接入提供边界。

组件主要职责
Desktop / CLI采集输入、呈现卡片和执行进展。
Product Service管理产品初始化、仓库绑定与生命周期。
Agent Service编排对话、模型调用、结构化交互与工具执行。
领域模块维护需求、变更等业务对象，检查状态与真实写入。
Viewer按角色只读展示文档、需求和待处理事项。

Viewer 可以保存展示偏好，业务操作则回到交互入口。查看资料与变更产品状态因此有明确分工。

推理模型与开发 Agent 独立配置

普通推理 API 通道支持 OpenAI、Claude API、DeepSeek 与 GLM，开发 Agent 通道目前面向 Codex App Server。两类配置分别选择服务、模型与推理强度，实际可用选项由配置和服务支持决定。

这使产品分析、调研、评审与编码可以采用各自合适的能力。外部 Agent 的任务范围和交付方式见 委派与交付。

同一份类型定义约束输入与校验

结构化输出以强类型模型定义数据形态，生成供模型使用的 JSON Schema，并用同一类型检查返回结果。例如卡片回答、执行计划与评审结论，各自有明确字段和允许值。

操作还关联当次上下文与约束。不同模型服务使用适合自身的格式适配，最终仍经本地校验，再由流程规则判断权限与语义条件。这样可以减少“发给模型的格式”与“执行时接受的格式”不一致。

Skill 按需提供工作方法

Skill 将需求澄清、文档编写、调研和评审等方法组织成可复用材料。系统按角色、工具与策略筛选索引，模型再按需读取完整方法和辅助资料，常用方法可以适量预加载。

工作方法可以独立更新，实际读写与状态改变通过注册工具或领域动作执行。方法说明、工具能力和执行权限各有维护位置。

MCP 工具接入统一执行目录

Northstar 通过 MCP 的标准输入输出（stdio）连接外部工具服务，读取工具描述与参数格式，按命名空间和允许范围加入工具目录。调用继续经过权限检查、审批策略与结果记录。

单个服务接入失败时记录该服务的问题，已经可用的工具可以继续工作。新接入工具的可操作范围由配置及工具契约确定。

长对话按预算组织上下文

每轮依据模型窗口分配历史、记忆、产品导航与工具结果的空间。较早讨论可以压缩为摘要和材料引用，原始对话保留用于回查，并周期性从原文重新整理摘要，减少连续压缩的累积偏差。

摘要与记忆帮助模型理解背景，正式状态和签核依据则来自对应业务记录。长对话需要继续引用当前材料，才能承接有效的产品上下文。

执行器统一管理工具边界

工具目录提供发现与描述，执行器检查调用参数、角色、保护规则和审批要求，再调用实际工具并保存结果。符合条件的只读调用可以并行，写入和状态操作遵循各自执行约束。
